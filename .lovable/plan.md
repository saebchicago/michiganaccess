# County pages: local programs, real economic and facility rows

## What I checked first

- The CDC Social Vulnerability and NCHS overdose feeds are **already ingested and real**: 83 counties of SVI (2022 vintage) and provisional overdose counts for the 12 months ending Dec 2025 - 30 counties with a published count, 53 withheld by NCHS because the count is under 10. Nothing is a placeholder there.
- County facility counts already come from a real extract (CMS certified hospitals plus active HRSA health center sites), regenerated by a script, not hand-typed.
- The county help panel exists on each brief, but its local listings lean on resource categories that barely exist outside a few counties (clinic-type rows exist in 3 counties), and only 3 of the 11 money-help programs are tied to a place. That is why it reads statewide.

So the remaining work is: make the rows that still say "no data" or "estimate" show real numbers, make the help panel genuinely local, and give it a page of its own.

## 1. Dedicated county help page

- New page at `/county/:slug/help`, linked from the help panel on the brief ("See every program in this county").
- The brief keeps a short version: the top two or three shortages. The page shows every shortage row, every unassessed row with the reason, and the full program list per shortage - no truncation to four entries.
- Page gets its own title, description and self-referencing canonical, and is added to the prerender list and sitemap so it is findable.

## 2. Real local programs behind each shortage

- New generated county program directory built from published sources, keyed to county FIPS:
  - HRSA health center service sites already in the verified facility extract (sliding-scale clinics - the real answer to a primary-care shortage).
  - MSHDA Housing Assessment Resource Agency list (one named agency per county) for housing cost burden.
  - Michigan Community Action agency service areas for energy and utility help.
  - MDHHS county office directory for coverage and food assistance intake.
  - Feeding America member food bank service areas for food rows.
- These load into `community_resources` and `financial_programs` through a seeded migration plus a refresh script, so every county has at least one named local entry per shortage it reports.
- The help panel and page then prefer local rows and only fall back to statewide, labelled. Where a shortage still has no local match, it says so plainly and gives 2-1-1.
- Shortage-to-program mapping stays in one module so brief and page cannot disagree, and category names are broadened to the values the data actually uses.

## 3. Economic rows stop being estimates

- New ACS county economic ingestor covering all 83 counties: median household income, poverty rate, child poverty rate, labor force participation. These render as verified rows with the ACS vintage, next to the existing unemployment rate.
- The modeled ALICE hardship and food-insecurity rows stay, keep their modeled label, and are moved below the published figures so a reader sees sourced numbers first.

## 4. Facility rows stop being one flat count

- The facility generator also emits a per-county breakdown: certified hospitals, hospital beds, and active health center sites, each with its source dataset.
- The brief shows the breakdown instead of a single number, which also removes the mismatch between the live directory and the static count.
- Existing facility guard extended to the new fields so a bad refresh fails the build.

## 5. SVI and overdose rows

Both feeds are populated, so the fix is presentation, not ingestion:
- Always render both rows. A withheld overdose count reads "fewer than 10 - withheld by NCHS", never 0 and never "no data".
- Overdose row prints the 12-month period; SVI row prints the vintage and the modeled label.

## Technical notes

- New ingestors follow the existing `scripts/refresh-*.mjs` shape: manifest-recorded fetch, county FIPS registry as join key, `--apply` / `--require-live`, never regressing a populated payload to a stub.
- Any generator added to the app build is added to the repo-root build too, or `check-build-parity` fails.
- Each new dataset gets a `dataCatalog` entry keyed to a `sourcesRegistry` feed, a freshness registry entry, and a nightly workflow.
- Migration order: create table, GRANT, enable RLS, policies. Program rows are public-readable; nothing writable by anonymous users.
- New route added to route taxonomy, prerender and sitemap guards.
- Verification: typecheck, unit tests, all integrity guards, and a spot check that a rural county (Keweenaw) and a metro county (Wayne) each show local programs and no fabricated zeros.

## Order

Ingestors first (economic, facility breakdown), then the program directory and seeding, then the help page, then the presentation fixes.
